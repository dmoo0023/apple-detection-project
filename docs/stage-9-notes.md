# Stage 9: Final comparison and test evaluation

## Decision table (val split, checkpoint C3)

| Method | Precision | Recall | F1 | mAP@0.5 | Median 3D proxy (cm) | Within 2cm | Within 3cm | sec/image | Robustness |
|---|---|---|---|---|---|---|---|---|---|
| Classical (colour masking) | 0.537 | 0.561 | 0.548 | 0.204 | 0.11 | 100.0% | 100.0% | 0.021 | fails under shade (recall collapses); undersizes circles from leaf occlusion |
| YOLO (`model-v1`) | 0.785 | 0.842 | 0.812 | 0.830 | 0.07 | 100.0% | 100.0% | 0.055 | handles shade much better; dominant failure is missed detections on clustered/touching apples; occasional false positives on background structures |

Generated by `scripts/stage9_decision_table.py`, which never touches test
(rule 3) — it builds the val split directly from `configs/splits.json`
and only reads test-excluded images.

A hybrid method (detector boxes + a classical circle fit for the centre)
was considered but not built: Stage 8's exp-06 already answered the
closely-related "how should the final centre be estimated" question
(box-centre beats mask-centroid under occlusion), and with YOLO already
winning on every accuracy axis by a wide margin, a hybrid's only plausible
upside would be speed — and classical's speed edge here (0.021s vs 0.055s
per image) is already small in absolute terms and not worth the added
pipeline complexity for this result. Worth revisiting only if inference
speed becomes an actual constraint later.

**3D proxy, within-2cm and within-3cm numbers read as 100% here only
because every matched apple's depth falls in the `out_of_range` band**
(the checkpoint-C1 depth-scale limitation) — the "within 2/3cm" figures
are of a *proxy* error, not literal accuracy against a physically measured
apple. See `docs/limitations.md`.

## Checkpoint C3: confirmed

Student confirmed YOLO (`model-v1`) as the chosen method, after reviewing
the full Stage 8 experiment series, seed repeats, and error analysis
(`EXPERIMENTS.md`, `docs/stage-8-notes.md`) plus this decision table. The
margin is not close on any accuracy metric — classical's only edge is a
small absolute speed advantage (both are fast enough in practice: 55ms vs
21ms per image).

## Locked test evaluation — DONE, `final-test-eval`

Run once, on a clean git tree (`src/tracking.py`'s `refuse_if_dirty()`
would have refused otherwise), by `scripts/run_final_test_eval.py`.
**This is the project's one and only look at test**, on the 20 labelled
images in rows 4 and 21 — rows the model had never seen in training or
validation at all.

| | Val (checkpoint C3 decision table) | **Test (final, locked)** |
|---|---|---|
| Precision | 0.785 | 0.753 |
| Recall | 0.842 | 0.761 |
| F1 | 0.812 | **0.757** |
| mAP@0.5 | 0.830 | **0.755** |
| Count MAE | 2.96 | 4.55 |
| Count bias | — | +0.45 |

**Test scores noticeably lower than val, reported plainly — this is
exactly what a held-out test set is for, not a problem to explain away.**
Some of val's rows (8, 9) were only added partway through labelling and
evaluated repeatedly as the model improved; test's rows were never looked
at until this single run. A ~5-7 point drop on every detection metric
going from "rows seen during development" to "rows never seen at all" is
a real, honest measurement of the generalisation gap this project's
earlier row-diversity checks (Stage 8) could only partially estimate.
Encouragingly, it's a drop, not a collapse — F1 and mAP both stayed above
0.75, consistent with the model having learned something about apples in
general, not just this orchard's already-seen rows.

One apple (`R04U13`, index 19) has no usable depth — `robust_depth()`
found too few valid pixels in its sampling disc and correctly reported
`None`/`"unknown"` rather than a fabricated value (rule 4). Its 2D
position is still matched and scored normally; only its depth-dependent
numbers (z, 3D proxy error, distance band) are excluded. This is the
pipeline working as designed, not a bug.

**Per the brief: no tuning happens after this.** If this result had been
worse, that would be the answer, not a cue to retune and re-run. Tagged
`final-test-eval`.
